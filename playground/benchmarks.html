📐 Methodology

Read the individual benchmark scripts and report metadata before comparing:

  • Dataset and operation: defined separately in each paired script
  • Warm-up and measurement: iteration counts vary; reported timings are means
  • Environment: new reports record runtime versions, concurrency, timeout, and measured commit
  • Ratios: backend time / Python time. Below 1 means faster than Python for that row, not an overall winner. Only successful, finite positive measurements can be compared.
  • Scope: direct kernel rows exercise registered kernels; existing workload rows reflect their paired scripts. Neither label demonstrates that normal TypeScript API methods dispatch to Wasm.
  • Rust/Wasm: runs under Bun. Verified timings require a binary hash and positive kernel-call receipt; no TypeScript fallback is counted as Wasm. Module loading and warm-up are outside the timed kernel region.
  • Missing results: unsupported, unverified, failed, and unselected backends remain visible. Older two-way reports show Wasm as “Not measured.”

🤖 About

The Pages workflow collects paired benchmark scripts and publishes their results when main changes. Timings alone do not establish semantic equivalence or approve a performance claim.
